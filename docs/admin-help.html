Přehled architektury

Fio Banka je multi-tenant aplikace hostovaná na Cloudflare Pages. Jeden GitHub repozitář (kód) → jeden CF Pages projekt (běh) → N klientů spravovaných přes admin panel.

Přihlášení do admin panelu

  1. Otevřete https://fio-banka-3ns.pages.dev/admin
  2. Zadejte admin heslo
  3. Zadejte 6-místný TOTP kód z Google Authenticator (pokud je MFA aktivní)
  4. Po přihlášení vidíte seznam klientů
⚠️ Pokud zapomenete heslo Heslo se ukládá v KV pod klíčem admin:password. Smažte ho přes wrangler kv key delete a fallback se vrátí k env varu ADMIN_SECRET (initial heslo z CF Secrets).

Správa klientů

Vytvoření nového klienta

  1. Klikněte + Novy klient
  2. Vyplňte:
    • ID — unikátní identifikátor (malá písmena, čísla, pomlčky), např. jan-novak. Bude použité v URL.
    • Název — zobrazované jméno klienta
    • Heslo — heslo pro klienta (předáte mu ho)
  3. Pro každý účet:
    • Zadejte Název účtu (např. "Běžný účet", "Spořicí")
    • Vložte Fio API klíč
    • Klikněte Test — ověří, že token je platný (vrátí číslo účtu, IBAN, měnu)
  4. Klikněte + Pridat ucet pro další účet
  5. Klikněte Ulozit
  6. Zkopírujte Link ze sloupce v tabulce a pošlete klientovi
✓ Best practice Před uložením vždy klikněte na Test u každého tokenu. Ušetří to klientovi zmatek pokud je token neplatný.

Úprava klienta

Klikněte Upravit u řádku klienta. Formulář se předvyplní:

  • ID — zamčené (nelze měnit)
  • Heslo — prázdné = zachovat stávající. Zadáte-li nové, klient bude muset projít TOTP enrollmentem znovu.
  • Účty — názvy předvyplněné, tokeny zobrazeny jako preview (abc12345...). Prázdné token pole = zachovat existující. Nová hodnota = přepsat.

Smazání klienta

Smazat → potvrdit. Tím zmizí z KV všechna data klienta (heslo, TOTP secret, Fio tokeny). Operace je nevratná.

Fio API tokeny

Jak získat Fio API token

  1. Klient se přihlásí do internetového bankovnictví Fio
  2. Nastavení → API → Přidat nový token
  3. Zvolí oprávnění (jen čtení stačí)
  4. Token zkopíruje a pošle vám
⚠️ Bezpečnost tokenů Token umožňuje číst všechny pohyby na účtu. Předávejte ho bezpečným kanálem (Signal, šifrovaný e-mail), ne přes Messenger/SMS.

Změna admin hesla

  1. V hlavičce admin panelu klikněte 🔑 Změnit heslo
  2. Zadejte stávající heslo
  3. Zadejte nové heslo (min. 6 znaků)
  4. Zopakujte nové heslo
  5. Klikněte Uložit

Heslo se uloží do KV pod klíčem admin:password. Env var ADMIN_SECRET zůstává jako recovery fallback.

Admin MFA (TOTP)

Admin login vyžaduje druhý faktor přes Google Authenticator jen pokud je nastavený env var ADMIN_TOTP_SECRET.

Aktivace MFA pro admina

  1. Vygenerujte base32 secret: 
    node -e "const c='ABCDEFGHIJKLMNOPQRSTUVWXYZ234567';const b=require('crypto').randomBytes(20);let s='';for(const x of b)s+=c[x%32];console.log(s)"
  2. Nastavte jako secret: 
    echo "VYGENEROVANY_SECRET" | npx wrangler pages secret put ADMIN_TOTP_SECRET --project-name fio-banka
  3. Přidejte do Google Authenticator (+ → Zadat klíč) jako FioBanka Admin
  4. Příště se přihlásíte heslem + TOTP kódem

Deaktivace MFA

npx wrangler pages secret delete ADMIN_TOTP_SECRET --project-name fio-banka

Audit log

Každý pokus o přihlášení (klient i admin, úspěšný i neúspěšný) se ukládá do KV pod klíčem audit:{timestamp}-{random} s TTL 90 dnů.

Retenční politika

Cloudflare KV automaticky maže klíče po expiraci (expirationTtl). Není potřeba manuální cleanup. Konstantu AUDIT_TTL_DAYS v functions/_shared/audit.js můžeš změnit:

  • 30 dnů — méně dat, GDPR-friendly
  • 90 dnů (default) — rozumný kompromis
  • 365 dnů — pro compliance audit
  • Bez TTL — odstranit expirationTtl, věčné záznamy (POZOR: vyžaduje manuální cleanup)

Otevřeš ho přes tlačítko 📜 Audit log v hlavičce admin panelu. Zobrazí se posledních 100 událostí seřazených od nejnovějších.

Typy událostí

TypeVýznam
admin_login_okAdmin se úspěšně přihlásil
admin_login_failAdmin login neúspěšný (reason: bad_password / bad_totp)
client_login_okKlient se úspěšně přihlásil
client_login_failKlient login neúspěšný (reason: no_client / bad_password / bad_totp)
client_login_needs_enrollmentKlient prošel heslem, čeká na TOTP enrollment

Každý záznam obsahuje: ts, type, clientId (kde aplikovatelné), reason, ip, country, ua (user-agent).

⚠️ Co sledovat Opakované *_login_fail z jedné IP = potenciální brute-force attack. Rate limiting zatím není implementovaný (M4 task pending) — pokud uvidíš podezřelou aktivitu, můžeš dočasně zablokovat IP přes Cloudflare WAF firewall rule.

IP Allowlist (whitelist)

Pro každého klienta lze omezit přístup z konkrétních IP adres nebo CIDR rozsahů. V editačním formuláři je textové pole IP Whitelist — jedna IP/CIDR na řádek.

Pravidla

ObsahVýznam
(prázdné)Bez omezení — povolený přístup z jakékoliv IP
*Bez omezení (explicitně)
1.2.3.4Jen tato konkrétní IP
10.0.0.0/24CIDR rozsah (256 adres)
1.2.3.4
5.6.7.0/24		Více IP/CIDR — povoleno když odpovídá kterémukoliv řádku
1.2.3.4
*		* má přednost = bez omezení

Stav v seznamu klientů

  • Neomezeno — allowlist je prázdný nebo obsahuje *
  • Omezeno (N) — N IP/CIDR pravidel, jen z nich je povoleno

Když je IP blokovaná

  • Server vrátí HTTP 403 a chybu "Přístup z této IP adresy není povolen"
  • Pokus je zalogován do audit logu s reason: ip_blocked
  • Heslo se neověřuje (rychlejší fail = nižší attack surface)
⚠️ Pozor na klientovu dynamickou IP Pokud klient používá domácí internet bez statické IP, jeho adresa se může změnit. Pro mobilní data je IP téměř vždy dynamická. Pro takové klienty buď nechej *, nebo zadej CIDR rozsah celé sítě jeho ISP (rizikovější).

Troubleshooting

Klient nemůže projít TOTP enrollmentem

  • Zkontrolujte čas na klientově telefonu (Authenticator je citlivý na drift)
  • Pokud klient zadal špatný kód moc krát, smažte mu TOTP a nech ho začít znovu — v admin panelu upravit klienta a změnit heslo (tím se vynuluje totpSecret a totpEnrolled)

Klient ztratil telefon s Google Authenticator

  1. Otevřete admin panel → Upravit klienta
  2. Nastavte mu nové heslo (i kdyby bylo stejné jako staré)
  3. Tím se vynuluje totpEnrolled → klient projde enrollmentem znovu s novým telefonem

Deploy selže s "Invalid commit message"

Cloudflare API odmítá emoji v git commit messages. Použijte:

npx wrangler pages deploy . --project-name fio-banka --branch main --commit-message "ASCII message"
